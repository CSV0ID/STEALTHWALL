# Security Policy

## Supported Versions

We actively maintain and provide security patches for the following versions of STEALTHWALL:

| Version | Supported          |
| ------- | ------------------ |
| 5.0.x   | :white_check_mark: |
| < 5.0   | :x:                |

---

## Reporting a Vulnerability

The STEALTHWALL team takes security vulnerabilities seriously. If you discover a security vulnerability, bypass, or potential exploit in the STEALTHWALL engine, please follow our responsible disclosure guidelines:

1. **Do not create a public GitHub issue** or post details publicly on social media before a patch is released.
2. Submit a private **[GitHub Security Advisory](https://github.com/CSV0ID/STEALTHWALL/security/advisories/new)** directly through the repository.
3. Alternatively, contact the maintainer directly via **[chinmayshinde.dev](https://chinmayshinde.dev)**.

### What to Include in Your Report:
- A clear description of the vulnerability and attack vector.
- Proof of Concept (PoC) script, HTTP payloads, or reproduction steps.
- The affected component (ASGI middleware, Express middleware, 0-day heuristic engine, ONNX pipeline).

### Response Timeline:
- **Initial Acknowledgment**: Within **24 hours**.
- **Vulnerability Assessment & Triage**: Within **48 hours**.
- **Patch Release**: Within **3 to 5 business days**.

We appreciate your effort in responsibly disclosing issues to help protect the open-source community.
