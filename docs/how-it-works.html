Architecture & Mathematical Specifications

How STEALTHWALL Detects & Mitigates Attacks

A sub-millisecond, four-stage defensive pipeline designed to detect automated reconnaissance, exploit bursts, and zero-day mutations before requests reach application business logic.

Pipeline

The 4-Stage Defense Lifecycle

Every incoming HTTP request traverses four specialized layers in under 0.8 milliseconds total.

1

Stage 1: Pre-Enforcement Kernel Gate

Before any request memory is allocated or Python/Node code runs, the kernel driver inspects local iptables / nftables IP sets. Known attackers, active cooldown IPs, and gated BGP ASNs are immediately dropped at the network interface with <0.02ms latency.

2

Stage 2: Sliding-Window Feature Extraction

For non-blocked IPs, the request timestamp, path, method, headers, and body are recorded in a high-speed in-memory ring buffer (or Redis cluster). A 60-second sliding time window computes 14 normalized mathematical metrics capturing behavioral entropy.

3

Stage 3: LightGBM ONNX AI Inference

The 14-float feature vector is passed to an ultra-optimized coldstart.onnx LightGBM model running via ONNX Runtime (with a pure-Python fallback). The model outputs a continuous anomaly score from 0.0000 (clean) to 1.0000 (critical exploit).

4

Stage 4: Graduated Response & Edge Sync

Rather than binary allow/block, STEALTHWALL applies proportional graduated tiers: rate_limit ➔ pow_challenge (cryptographic bot puzzle) ➔ provisional_block ➔ temp_block. Concurrently, edge rules are pushed to Cloudflare WAF and AWS Security Groups.

Feature Extraction Spec v1

The 14 Statistical Features

Normalized to [0.0, 1.0] with cross-language bit-for-bit mathematical parity between Python and Node.js.

# Feature Key Mathematical Formulation Threat Signal Detected
01 request_rate min(1.0, count(events) / 60.0) Volumetric DoS bursts & rapid scanner threads
02 unique_path_ratio count(unique_paths) / count(events) Directory enumeration (Nikto, DirBuster, ffuf)
03 path_entropy -sum(p * log2(p)) / log2(n) Randomized URL fuzzing & parameter sweeps
04 notfound_ratio count(status == 404) / count(events) Exploit path probes looking for unpatched CVEs
05 auth_failure_ratio count(status == 401 on /login) / count(events) Credential stuffing & brute-force logins (Hydra, WPScan)
06 avg_payload_entropy sum(byte_entropy(payload)) / count(events) Encrypted/obfuscated/shellcode POST payloads
07 signature_score count(sig_matches in path+body) / count(events) SQLi, XSS, Path Traversal, JNDI keyword presence
08 timing_variance population_variance(delta_ts) Automated bots with clockwork intervals vs humans
09 header_anomaly_score missing_expected_headers / 4.0 Headless scripts with missing Host/Accept/User-Agent
10 method_post_ratio count(method == POST) / count(events) API exploit injection bursts & form spamming
11 avg_path_depth sum(slash_count(path)) / count(events) Deep nested directory traversal (../../etc/passwd)
12 digit_ratio_in_path digit_chars / total_chars ID enumeration sweeps (/item/1, /item/2, ...)
13 user_agent_entropy byte_entropy(user_agent) Spoofed or randomized scanner User-Agent headers
14 window_utilization count(events) / WINDOW_MAX_EVENTS Window saturation velocity
Heuristic AI Layer

The 0-Day & Novel Mutation Threat Engine

How STEALTHWALL detects zero-day vulnerabilities even when models are frozen at deploy time.

🔍

SSRF & Cloud Metadata Defense

Detects attempts to query internal cloud credentials via 169.254.169.254, metadata.google.internal, and latest/meta-data in both query parameters and POST JSON bodies.

⚡

JNDI, Log4j & Deserialization

Intercepts remote code execution gadgets such as ${jndi:ldap:, ${jndi:rmi:, XML External Entity (XXE) expansion (<!ENTITY), and Java object deserialization chains.

🧬

Polymorphic & Prototype Pollution

Identifies JavaScript object override attempts (__proto__, constructor.prototype) and double-URL/hex encoded payloads (%2527, \x27, \u0027) designed to evade regex WAFs.
